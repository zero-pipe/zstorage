# 云存储旁路录制 · 完整规范（Go 控制面 + C 数据面，MPEG-PS 槽位封装）

> 读者：执行本方案的工程师 / AI。本文是**唯一契约**，改代码前对齐本文。
> 落盘格式：**MPEG-PS**（写成预分配槽位 `.zslot`，内含标准 PS 数据区 + 关键帧索引）。
> 前提（已拍板）：zstorage 是独立存储节点（独立注册、独立表、自理回放），录制是从 ZMS 主动拉流旁路录制。

---

## 0. 与"独立 .ps 切片方案"的差异澄清（重要，勿照搬）

参考方案用"每段一个 `.ps` 文件 + 每次回放自建索引/扫 NALU 找关键帧"。本系统**已经实现更优的槽位模型**，映射关系如下，**实现以本系统为准**：

| 参考方案概念 | 本系统真实实现 | 说明 |
|---|---|---|
| 每段一个 `.ps` 文件 | 预分配槽位文件 `.zslot`（固定大小循环复用） | 断电可恢复；删除不释放磁盘，回收复用 |
| 自建 `.idx` / 二分扫 NALU 找关键帧 | **槽位头 Zone B 自带关键帧索引**（`utc_ms/pts_90k/file_offset`，二分查找） | seek 定位 O(log n)，无需扫码流 |
| `.ps.tmp` → rename `.ps` | 槽位三态 `FREE/WRITING/SEALED`；封口即改状态位 | 崩溃后扫 PS pack 链恢复 WRITING→SEALED |
| C 推流到外部流媒体服务 | zstorage 本身带 FLV/RTSP/WebRTC 出口 | 无需外推，直接出流，平台拿地址 |
| `record_segment` 新表 | 复用 `zws_cloud_record`（前端已在用） | 只扩列，不新建 |
| `record_plan/record_plan_schedule/record_plan_channel` 新表 | 已有 `zws_record_plan` / `zws_record_plan_item` / `zws_channel_ext.record_plan_id` | 只扩列，不新建 |

净结论：**参考方案里最难/最容易出错的部分（切片、索引、断电恢复）我们已用槽位模型解决且更优**；本规范只补"控制面编排、注册、查询、回放"的契约。

## 1. 职责边界（控制面 / 数据面分离）

- **控制面 = zero-web-server（Go）**
  - 录像计划/时段/通道绑定配置；定时扫描算"谁该录"；启停裁决；录像索引查询；过期清理下发。
  - **不直接读写 `.zslot` 磁盘文件**；不解析 PS。
  - 维护 `zws_cloud_record`（前端时间轴唯一数据源）、`zws_storage_node`（存储节点）。
- **数据面 = zstorage（C）**
  - 接收控制面的录制任务（channel_key + 拉流 URL）→ 拉流 → 复用 PS → 写槽位 → 封口。
  - 维护槽位池/索引/断电恢复/过期回收；提供**录像查询**与**回放出流**（含 seek 重推）。
  - **不连业务主 MySQL**；只通过 HTTP 与平台交互。
- **取流源 = zmedia-server（ZMS）**：zstorage 从它的 `rtsp://…/live/<流名>` 拉流；ZMS 的 MP4 录制逻辑完全不动。

## 2. 数据与状态归属

### 2.1 Go 平台（MySQL）— **扩已有表，不新建重复表**

**表 A：`zws_storage_node`（新增，独立于 `zws_media_server`）**
存储节点注册表。**不复用媒体节点表**（`Resolve/SelectMinimumLoad` 选取流节点不按 type 过滤，混表会被误当选流节点）。
```sql
CREATE TABLE IF NOT EXISTS zws_storage_node (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  node_id      VARCHAR(128) NOT NULL,           -- zstorage 上报 media_server_id
  name         VARCHAR(128) DEFAULT '',
  ip           VARCHAR(64)  NOT NULL,           -- 控制面/出流可达 IP
  http_port    INT NOT NULL,                    -- zstorage HTTP/API/FLV 端口
  rtsp_port    INT DEFAULT 0,
  secret       VARCHAR(128) DEFAULT '',         -- 与 zstorage [api] secret 一致
  version      VARCHAR(64)  DEFAULT '',
  capacity_gb  INT  DEFAULT 0,
  used_gb      INT  DEFAULT 0,
  online       TINYINT(1) DEFAULT 0,
  last_seen    BIGINT DEFAULT 0,
  default_node TINYINT(1) DEFAULT 0,
  create_time  VARCHAR(50) DEFAULT '',
  update_time  VARCHAR(50) DEFAULT '',
  UNIQUE KEY uk_storage_node_id (node_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='云存储节点';
```

**表 B：`zws_record_plan` / `zws_record_plan_item`（已有，扩展）**
- `zws_record_plan` 增列：`record_mode TINYINT DEFAULT 1`（1 定时/2 告警/3 手动）、`segment_sec INT DEFAULT 300`、`keep_days INT DEFAULT 7`、`enabled TINYINT DEFAULT 1`。
- `zws_record_plan_item` 已有 `week_day/start_min/stop_min`（**分钟粒度**，够用，不改成秒）。

**表 C：`zws_channel_ext`（已有，扩展）**
增列：`storage_node_id VARCHAR(128) DEFAULT NULL`（该通道录到哪个存储节点；空=默认节点或不录）。
`record_plan_id` 已存在，作为"通道→计划"绑定（等价参考方案的 `record_plan_channel`，不再新建）。

**表 D：`zws_cloud_record`（已有，扩展）**
这是前端时间轴与回放的**唯一数据源**。增列：
- `storage_node_id VARCHAR(128) DEFAULT NULL`（录制所在存储节点 node_id）
- `container_format VARCHAR(16) DEFAULT 'mp4'`（`mp4` | `ps`，区分来源）
- `slot_id INT DEFAULT 0`（PS 槽位号，回放定位用；MP4 为 0）
- `record_type TINYINT DEFAULT 1`
- `status TINYINT DEFAULT 2`（1 录制中/2 正常/3 残片恢复/4 已清理）
现有 `start_time/end_time/time_len/file_size/file_path/play_url/media_server_id` 沿用。
> `media_server_id` 在 PS 来源时存**存储节点 node_id**（便于 Resolve 到 zstorage），API 层不区分。

**Redis（控制面实时态，可选，先可只用内存）**
- `rec:desired:{channel_id}`：期望态（should_record/plan_id/record_type/segment_sec/node_id）。
- `rec:runtime:{channel_id}`：实际态（recording/record_task_id(=channel_key)/node_id/last_error/updated_ms）。

### 2.2 zstorage（C）本地状态
- 内存：录制任务表（channel_key→拉流代理+录制器）、槽位池、槽位索引。
- 槽位文件：`{storage.dir}/slot_%08d.zslot`（预分配，FIXED 大小）。
- 槽位头：`stream`(=channel_key)、`state`、`seg_start/end_utc_ms`、`keyframe_count`、关键帧索引表。
- **无独立 SQLite**（参考的本地快照可选；本系统靠槽位头自描述做崩溃恢复，不引入 SQLite）。

## 4. 接口与边界（Go ↔ C）

### 4.1 通信规则
- Go→C：HTTP/JSON 同步控制接口，带 `request_id` + 超时 + 重试。
- C→Go：HTTP/JSON 异步事件回调，带全局唯一 `event_id`，Go 幂等，C 失败重试（本地队列）。
- 统一响应体 `{code,msg,data}`，鉴权 `?secret=`。
- 路径统一挂 `/index/api/zstorage/`（A 族控制面）。

### 4.2 Go → C 控制接口

| 接口 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `zstorage/record/start` | POST/GET | `request_id, channel, url, stream_id?, record_type?` | `data.record_task_id(=channel), data.state` |
| `zstorage/record/stop` | POST/GET | `request_id, channel` | `data.closed_segments`（本次封口段数，附带走回调） |
| `zstorage/record/delete` | POST | `request_id, slots[]` 或 `channel + before_ms` | `data.deleted_slots[], data.failed_slots[]` |
| `zstorage/record/query` | GET | `channel?, start, end` | `data.segments[]`（见 §5） |
| `zstorage/node/status` | GET | — | `node_id, disk_total_bytes, disk_free_bytes, active_tasks, capacity_gb, used_gb` |
| `zstorage/playback/start` | POST/GET | `request_id, playback_session_id, channel, start, end, scale?` | `data.stream, data.urls{flv,rtsp,...}, data.actual_start_ms` |
| `zstorage/playback/seek` | POST/GET | `request_id, playback_session_id/stream, seek_ms` | `data.actual_time_ms`（对齐到的关键帧时间） |
| `zstorage/playback/stop` | POST/GET | `request_id, stream` | — |

> 注：`record/delete` 参考方案是"按 file_paths 删"，本系统按**槽位号**删（槽位是磁盘单位），语义一致。

### 4.3 C → Go 回调（zstorage → 平台）

**回调 1：切片完成 `POST /index/hook/on_record_ps`**（每次槽位封口发一次）
```json
{ "event_id":"evt_...", "mediaServerId":"zs-1", "channel":"1001_0001",
  "slot":42, "startTime":1795703282188, "endTime":1795703318570,
  "durationMs":36382, "fileSize":2260720, "filePath":"slot_00000042.zslot",
  "status":2 }
```
平台 `on_record_ps` → 写 `zws_cloud_record`（`container_format=ps, slot_id=42, storage_node_id=node_id, play_url=zstorage 回放入口`）。**按 (node_id, slot) 幂等**。

**回调 2：异常/状态 `POST /index/hook/on_storage_event`**（可选，一期可省）
```json
{ "event_id":"evt_...", "channel":"...", "event_type":"ERROR|DISK_LOW|RECOVERED",
  "error_code":"DISK_FULL", "occurTimeMs":1795718500000 }
```

- 入参：`channel?`、`start_ms`、`end_ms`（查有重叠的已封口槽位）。
- 出参：
```json
{ "code":0, "data":{ "total":2, "segments":[
  {"slot":1,"channel":"1001_0001","start":1795703282188,"end":1795703318570,"size":2260720},
  {"slot":2,"channel":"1001_0001","start":1795703319316,"end":1795703356871,"size":..} ]}}
```

## 6. 回放设计（数据面在 zstorage 内部，复用现有出流链路）

### 6.1 会话模型（照 `gb_playback.c` + 槽位索引）
```
playback/start(channel,start,end)
 │ zs_pool_find_range_stream(channel,[start,end]) → 命中有序槽位段
 │ 逐段：zs_pool_open_slot → zslot demuxer 解 PS → zms_vod_buffer(write)
 │       → vod_buffer_reader → muxed ES → 灌入 media_source.gop_queue
 │ media_source 以 live/<channel>_playback 注册 → 现有 FLV/RTSP/WebRTC 出口出流
 ▼ 返回 {stream, urls}（与 ZMS StreamContent 同构，前端 playerTabs 零改动）
```

### 6.2 拖动 = 重新定位续推（Seek）
```
playback/seek(stream, T)
 │ 定 T 所属槽位：zs_pool_find_range_stream(channel,[T,T])
 │ 槽位内定位：zs_slot_find(slot,T) → 取 <=T 最近关键帧的 file_offset（索引二分，O(log n)）
 │ reader 跳该 offset，清空旧 GOP，从关键帧续推
 ▼ 返回 actual_time_ms（关键帧绝对时间）
```
- **不用换 URL**：同一 stream 名，播放器只是收到新 GOP（关键帧起）。
- **防乱序**：seek 带会话内序号，丢弃过期的旧读帧任务（参考方案"快速拖动防乱序"）。
- **跨槽无缝**：第 N 段读完自动续第 N+1 段，时间戳由 `zs_clock` 归一，进度条连续。

### 6.3 时间戳连续性
- 槽位内 PTS 已是 64 位归一化（`zs_clock`），跨槽/跨重连用绝对 UTC 对齐；出流时相对 `actual_start_ms` 换算，避免跳变。

## 7. 完整交互流程

### 7.1 计划录制启动 + 切片循环
1. Go 调度器周期（分钟）扫 `zws_record_plan(enabled=1)` + `zws_record_plan_item` + `zws_channel_ext.record_plan_id`，算当前应录通道 → 更新 `rec:desired`。
2. 对比 `rec:desired` 与 `rec:runtime`：应录未录 →
   - 解析存储节点（`channel_ext.storage_node_id` 或默认）；
   - 拼拉流 URL `rtsp://<ZMS streamIp>:<port>/live/<设备内码>_<通道内码>`（ZMS 取流节点由 `device.media_server_id` 解析）；
   - `zstorage/record/start(channel_key=内码_内码, url)`。
3. zstorage 拉流→写槽位，返回 `record_task_id`；Go 更新 `rec:runtime=录制中`。
4. 每当槽位满（`slot_size_mb`）/达 `slot_max_second`/`segment_sec`（关键帧处切）→ 封口 → 发 `on_record_ps` → Go 写 `zws_cloud_record`（幂等入队重试）。
5. 与现有 MP4 分支**并存独立**（同一路可既录 MP4 又旁路录 PS；互不共享 enable_mp4）。

### 7.2 停止录制
计划时段结束/禁用/手动 → Go 更新 `rec:desired=停止` → `zstorage/record/stop(channel)` → zstorage 封口当前槽位（触发一次 `on_record_ps`）→ Go 更新 `rec:runtime=未录制`。

### 7.3 崩溃恢复（zstorage 进程）
启动时池扫描：WRITING 槽位→扫 PS pack 链确定 `data_write_off`→改 SEALED（或以 status=3 "残片恢复"上报）。已实现。
平台侧：对账任务拉 `record/query` 补齐缺失的 `zws_cloud_record`；随后按 `rec:desired` 决定是否重发 start。

### 7.4 过期清理
Go 清理任务按 `zws_record_plan.keep_days` 查 `zws_cloud_record` 过期记录（batch）→ `zstorage/record/delete(slots[])` → zstorage 回收槽位返回成功/失败 → Go 按成功项把记录置 `status=4`（或删）。
> 磁盘语义：槽位回收即复用，不物理扩缩容；容量由池按 `capacity_gb` 上限 + `retention_days` 双控。

### 7.5 回放 + 拖动（见 §6）
播放器走 `/api/v1/playback/*` 或 `/api/v1/cloud/record/loadRecord`；平台判定该录像属 zstorage（`zws_cloud_record.storage_node_id` 非空）→ 转 `zstorage/playback/*`；返回值与 ZMS 同构，前端零改动。拖动 → `playback/seek`。
